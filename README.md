## Назначение

`hse-lms-harvest` открывает Smart LMS или выбранный модуль Netology через отдельный локальный браузерный профиль и сохраняет учебный контекст: компактный Markdown для агента, полную структуру страниц в JSON, вложения и диагностику.

По умолчанию сборщик читает видимое содержимое и раскрывает страницы с условиями заданий, включая «Добавить ответ на задание». Формы не отправляются, состояние курса не меняется.

| Возможность | Результат |
| --- | --- |
| Сбор через браузер | Использует страницы, доступные пользователю после входа. |
| Компактное представление | `navigation.md`, `summary.md` и `pages/*.md` экономят контекст агента. |
| Полная структура | `manifest.json` и `pages/*.json` сохраняют ссылки, кнопки, сведения о файлах и ошибки после фильтрации при сборе. |
| Учебные вложения | Скачивает файлы с того же сайта, включая обычные Moodle URL `pluginfile.php`, с повторным использованием кэша. |
| Фильтрация | Исключает личные отправленные работы, разделы оценок, сообщений, календаря и вторичные отчётные страницы. |
| Диагностика | Сохраняет структурированные сведения об ошибках; полный HTML по умолчанию не записывается. |

## Быстрый запуск

Нужны Python 3.11+, `uv` и установленный Chrome: его используют сборщик и локальные браузерные регрессии в `make check`.

```bash
cd hse-lms-harvest
uv sync --extra dev
make check
```

Сначала настройте установленный внешний помощник хранения пароля. Команда запрашивает пароль без отображения; в `.env` сохраняются только имя пользователя, путь помощника и имя сервиса:

```bash
uv run hse-lms-harvest credentials set \
  --username "student@example.edu" \
  --credential-helper "/absolute/path/to/study-keychain" \
  --env-file ".env"
```

Помощник — отдельный исполняемый файл. Его абсолютный путь обязателен при настройке и сохраняется как `HSE_LMS_CREDENTIAL_HELPER`. Один вызов обменивается одним JSON-запросом и ответом через stdin/stdout:

- Запрос содержит `operation` (`get`, `put`, `check`, `delete`), `account` и `service` (`codex-study-lms`); для `put` также передаётся `secret`.
- Успешный `get` возвращает `secret`, остальные успешные операции — `{}`. Ошибка содержит поле `error`: `not-found`, `locked`, `interaction-required`, `access-denied` или `user-canceled`.
- Помощник работает без интерактивных подтверждений; таймаут вызова — 10 секунд. Пароль не передаётся в аргументах, переменных окружения или диагностике. Для настройки из другого процесса есть `credentials set --password-stdin`.

`credentials status --env-file .env` проверяет доступность через `check`, не запрашивая пароль. `credentials delete --env-file .env` удаляет секрет и локальную конфигурацию. `HSE_LMS_PASSWORD` не читается ни из `.env`, ни из окружения. При переходе на помощник выполните `credentials set` с существующим паролем: прежняя запись удаляется после успешного сохранения и обратного чтения. Фоновый вход сообщает о недоступном секрете или ошибке авторизации и не ждёт ручного ввода.

Сбор курса:

```bash
uv run hse-lms-harvest harvest \
  --url "https://edu.hse.ru/my/courses.php" \
  --profile ".browser-profile" \
  --out "dumps" \
  --course-title "Course title" \
  --max-pages 260 \
  --download-files \
  --ensure-login \
  --auto-login \
  --headless
```

Список команд:

```bash
make help
uv run hse-lms-harvest --help
```

Для Netology указывайте URL расписания ровно одного актуального модуля и отдельный профиль. `--assignments-only` ограничивает обход расписанием, практикой и доступными заданиями. Условие домашней работы в Netology скрыто до нажатия «Приступить к заданию»: только явный `--open-netology-assignments` открывает её и ждёт полного текста. Это меняет статус задания; решение не отправляется. После открытия сравнивайте срок из списка практики с правилом срока внутри задания. Если вход требует CAPTCHA, её проходит пользователь в окне `login`, без автоматического обхода.

```bash
uv run hse-lms-harvest harvest \
  --url "https://netology.ru/profile/program/EXACT-MODULE/schedule" \
  --profile ".browser-profile-netology" --env-file ".env.netology" \
  --out "dumps/netology-current/MODULE" --headless --ensure-login --auto-login \
  --assignments-only --open-netology-assignments --download-files --page-cache off
```

## Результат сбора

Каждый запуск создаёт `dumps/<host>-YYYYMMDD-HHMMSS-microseconds/`:

| Путь | Назначение |
| --- | --- |
| `manifest.json` | Машинный источник данных после фильтрации при сборе. |
| `navigation.md` | Вход для агента: дерево страниц и локальные ссылки на Markdown, JSON и файлы. |
| `navigation.json` | Машинная навигация без URL LMS. |
| `summary.md` | Краткая сводка без внутренних индексов. |
| `pages/*.md` | Текст без повторов навигации, служебных URL, хешей и адресов действий. |
| `pages/*.json` | Полная структура страницы: текст, ссылки, кнопки, скачанные файлы и ошибки. |
| `files/` | Вложения, скачанные с `--download-files`. |
| `debug/errors.md` | Краткий индекс ошибок со ссылками на подробную диагностику. |

В Markdown текст гиперссылки сохраняется как обычный текст; полный URL находится в JSON. Для отладки сначала читайте `debug/errors.md`; подробности — в `debug/errors.json`, `debug/errors/<id>/` и `debug/events.jsonl`. Эти приватные материалы не входят в основной контекст агента. `--debug-dump-mode on-error` включён по умолчанию; `verbose` дополнительно сохраняет HTML, `off` отключает пакеты диагностики. Скриншоты отдельно отключаются через `--screenshot-mode off`.

`manifest.json` использует `format_version: 3`. Полнота записывается отдельно в `coverage` версии 1:

| Поле | Смысл |
| --- | --- |
| `status` | `complete` — очередь исчерпана и нужные страницы/вложения подтверждены; `partial` — осталась работа или ошибка захвата; `unknown` — включено доверие к кэшу без проверки. |
| `scope` | Разрешённый URL курса `source_url`, `capture_version`, параметры раскрытия/ожидания/ресурсов страницы и отбора ссылок/вложений. Это область для сопоставления снимков; `max_pages` и способ поиска курса в неё не входят. |
| `confirmed_urls` | URL исходных страниц (`page.url` без фрагмента), чей захват и нужные вложения подтверждены в этом запуске. Для `unknown` список пуст. |
| `remaining_urls` | Очередь отложенных и ошибочных URL; непройденные имеют приоритет перед повтором ошибки. |
| `stop_reason` | `exhausted`, `max_pages`, `capture_error`, `interrupted` или `unverified_cache`. |

Успех команды (`0`) означает `complete`; неполный или непроверенный результат возвращает `1`, сохраняя пригодные данные. Последняя строка stdout — `HARVEST_RESULT {"manifest_path":"/absolute/path/manifest.json","coverage_status":"partial","coverage_version":1}`. Потребитель проверяет соответствующий manifest, принимает изменения только из `confirmed_urls`, а удаление — из полного снимка с сопоставимым `scope`. Предупреждение о `networkidle`, закрытии браузера или отказе HEAD при успешном GET не делает результат неполным; ошибка HTTP, извлечения или нужного вложения делает.

`--max-pages` ограничивает новую/ранее неподтверждённую работу за запуск. `--resume-dump /path/to/dump` продолжает частичный обход той же области, `--resume-latest` делает это для последнего совместимого частичного дампа автоматически; иначе начинает новый обход. Подтверждённые страницы снова проверяются и не расходуют лимит порции: по совпавшим валидаторам без браузерного захвата, при недостатке сведений — новым захватом. Текущий корень определяет достижимость: удалённая ссылка не возвращается из прежней очереди. Вложения проверяются независимо от HTML. Очередь и страницы атомарно записываются в manifest после каждой страницы; при прерывании повтор безопасно перепроверяет незавершённое. `--page-cache off` несовместим с продолжением.

`--page-concurrency 2` открывает до двух независимых страниц курса одновременно после корня; предел — 3, умолчание — 1. Результаты и найденные ссылки записываются в исходном порядке, загрузка вложений сериализована. `debug/events.jsonl` содержит время открытия, подготовки, чтения текста и файлов каждой страницы. Для Netology оставляйте 1 из-за шагов открытия заданий. На длинном курсе истории два окна сократили полный обход 97 страниц с 188 до 159 секунд; три окна не дали заметного дальнейшего выигрыша. Режим кэша и подтверждение полноты от числа окон не меняются.

Обычный запуск без `--resume-*` заново обходит область с заданным лимитом. Сбор не является атомарным снимком сервера: `complete` подтверждает обход по заданным правилам, а изменения источника между запросами обнаруживаются следующей проверкой. Старые дампы без `coverage` остаются с неизвестной полнотой, в том числе после `migrate`.

Если изменилось только оформление, пересоберите представление из существующего дампа без обращения к LMS:

```bash
uv run hse-lms-harvest migrate --out dumps/current-subjects
```

## Нагрузка и повторное использование

- `--download-files` включает учебные вложения с того же сайта. `--skip-lms-file-server` явно отключает скачивание `pluginfile.php` и `/webservice/pluginfile.php`, сохраняя ссылки.
- Перед скачиванием выполняется короткий `HEAD` для проверки типа и размера; `--file-head-timeout-ms 0` отключает его. Лимит задаётся через `--max-file-mb`, параллельность — через `--download-concurrency`.
- Файловый кэш включён в `dumps/_file-cache`; `--no-file-cache` отключает его. Повторное использование требует совпавшего ETag либо Last-Modified вместе с размером; неизвестные метаданные и совпадение только размера/типа требуют загрузки. Если HEAD не подтверждает актуальность, выполняется условный GET с валидатором сохранённого файла: 304 использует целую локальную копию, 200 сохраняет новое содержимое. При отсутствии валидатора GET загружает содержимое целиком. Перед повтором проверяется SHA-256 локального файла, поэтому повреждение через жёсткую ссылку тоже обнаруживается. В одном запуске результат проверки используется повторно, пока признаки файла неизменны. `--trust-file-cache` отключает сетевую проверку, сохраняя проверку целостности; полнота такого запуска — `unknown`.
- Для страниц по умолчанию действует `--page-cache validate`: сравнение HTTP-валидаторов, сначала через `HEAD`, затем при необходимости через запрос метаданных `GET`. Повтор требует совместимых настроек и версии захвата, целого содержимого страницы и отсутствия ошибок извлечения. Вложения проходят отдельную проверку: изменённый или отсутствующий файл восстанавливается без повторного захвата пригодного HTML. `--page-cache trust` пропускает сетевую проверку HTML и даёт `unknown`. Старые страницы без сведений о версии/настройках захватываются заново; миграция оформления остаётся локальной.
- Изображения, шрифты, аудио и видео страницы блокируются; `--load-page-assets` включает их. Общее ожидание `networkidle` отключено, а корень курса получает короткое ожидание `--course-network-idle-timeout-ms` для лениво загружаемого оглавления.

Очистку сначала можно просмотреть с `cleanup --all --dry-run`. `cleanup --all` удаляет восстанавливаемые тяжёлые артефакты и браузерный кэш; полезные документы сохраняются. Файловый кэш очищается отдельно через явный `cleanup --file-cache`.

<a id="safety"></a>

## Безопасность

- `.env`, `.browser-profile/`, `dumps/`, cookies, скриншоты и логи исключены из Git; их содержимое остаётся приватным.
- По умолчанию сборщик не нажимает «Сохранить», «Отправить», «Удалить» и другие кнопки изменения состояния. `--allow-state-changes` разрешает только отметку выполнения, но не отправку, сохранение или удаление. Отдельный флаг `--open-netology-assignments` разрешает только «Приступить к заданию» на странице выбранного модуля Netology; отправка решения остаётся запрещена.
- Аудио, видео и артефакты конференций пропускаются; `--download-media` включайте, когда нужен именно медиаархив.
- Личные ответы из `assignsubmission_file/submission_files` исключены из скачивания, ссылок и текста. `--skip-action-pages` отключает чтение дополнительных страниц условий задания.
- Тесты используют локальные фикстуры и `about:blank`, без запросов к живой LMS.

## Проверки

```bash
make check
make doctor
make smoke
```

`make smoke` использует `about:blank` и временные каталоги, поэтому доступ к LMS не требуется. Проверки по типу изменения описаны в [AGENTS.md](AGENTS.md).

## Устройство проекта

| Путь | Назначение |
| --- | --- |
| `src/hse_lms_harvest/cli.py`, `cli_args.py` | Команды, параметры, настройки по умолчанию и очередь страниц. |

| `src/hse_lms_harvest/downloads.py`, `file_cache.py`, `page_cache.py` | Скачивание, ограничения, проверка и повторное использование файлов и страниц. |

| `src/hse_lms_harvest/debug.py`, `privacy.py`, `cleanup.py` | Диагностика, скрытие приватных значений и очистка артефактов. |
| `tests/` | Проверки контрактов без запросов к живой LMS. |
